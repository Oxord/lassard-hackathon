## Что сделать владельцу или maintainer

1. Открыть [Settings → Pages](https://github.com/Oxord/lassard-hackathon/settings/pages).
2. В `Build and deployment → Source` выбрать `GitHub Actions`. Workflow уже существует в `.github/workflows/pages.yml`; создавать второй не нужно.
3. В [Actions → Deploy 3D to GitHub Pages](https://github.com/Oxord/lassard-hackathon/actions/workflows/pages.yml) выполнить `Run workflow`, выбрав `main`. Это опубликует текущую main; изменения из открытых PR туда еще не включены.
4. Дождаться успеха обеих задач — `build` и `deploy`. Если есть запрос одобрения окружения `github-pages`, его обрабатывает ответственный за окружение.
5. Взять точный URL из результата `deploy`/Settings Pages. Ожидаемый адрес: `https://oxord.github.io/lassard-hackathon/`; при изменении настройки использовать фактический.

Изменение только документов в main не запускает текущий workflow автоматически: фильтр реагирует на `3d/**` и `.github/workflows/pages.yml`. Для публикации после включения Pages предусмотрен ручной запуск.

## Проверка перед внесением ссылки в ЛК

Из корня репозитория, Python 3, без дополнительных библиотек и без входа в GitHub:

```sh
python scripts/check_pages.py
```

Для другого фактического адреса:

```sh
python scripts/check_pages.py https://example.github.io/lassard-hackathon/
```

Скрипт проверяет HTML, наличие контейнера модели, доступность входного JS-модуля и подключенных CSS по адресам из опубликованной страницы. HTTP 404, пустые файлы и HTML вместо JS/CSS дают `ok: false` и код завершения 1. Успех — `ok: true`, код 0. Скрипт не исполняет JavaScript и не подтверждает работоспособность WebGL, динамических загрузок или правильность геометрии.

После успешной проверки открыть сайт в приватном окне браузера и проверить:

- модель отрисована, консоль не содержит ошибок загрузки;
- переключаются четыре сценария, открываются карточки зон;
- работают вид сверху, маршрут и автотур;
- узкий экран позволяет пользоваться кнопками; исправление в [PR #7](https://github.com/Oxord/lassard-hackathon/pull/7) появится на сайте только после его слияния и публикации;
- отдельно проверить `?tour=1` и `?tour=1&clean=1`, если эти ссылки нужны для показа.

В ЛК внести основной URL после проверки. Доступа к ЛК в этой задаче не было; внесение ссылки не выполнено. Зафиксировать время, опубликованный commit, URL и кто внес его в ЛК. QR и ссылку в финальных слайдах делать по тому же проверенному адресу. Старое видео `video/flythrough.mp4` не использовать: оно показывает прежнюю раскладку.
